# TeliGent - Intelligent Telegram Bot Manager (SaaS)

## Overview
TeliGent is a multi-tenant SaaS platform designed for managing AI-powered Telegram group bots. Its primary purpose is to provide advanced AI capabilities for community management, scam prevention, and real-time content moderation within Telegram groups. The platform aims to detect and counter various types of scams using deterministic rules and AI, offering a robust, scalable, and secure solution with isolated configurations and data for multiple bots per user. Key capabilities include AI-driven scam detection, real-time learning, configurable rewards systems, and an embeddable chat widget.

## System Architecture
**Frontend**: Built with React, TypeScript, Vite, Shadcn UI, TanStack Query, and Wouter. Features a minimal UI with a monochrome palette. An embeddable chat widget (`client/public/widget.js`) integrates AI, knowledge base, and memory for website support.
**Backend**: Utilizes Express.js with Drizzle ORM for PostgreSQL.
**Authentication**: Custom email/password system with bcrypt and express-session. Includes email verification and self-serve password recovery via single-use, hashed, expiring tokens (24h verify, 60min reset). Outbound email goes through `server/email/mailer.ts`, which uses Resend (sending domain `in.teli.gent`, From `TeliGent <noreply@in.teli.gent>` via `MAIL_FROM` env var, API key in `RESEND_API_KEY` secret) and falls back to a console-log stub when no key is set. The `requireVerifiedEmail` middleware gates paid actions (`/api/billing/checkout`, `/api/billing/crypto/intent`, `/api/bots/:id/erc8004/register`). Public pages `/forgot-password`, `/reset-password`, and `/verify-email` are accessible without a session. A successful password reset force-deletes all other sessions for that user. Email-link origin is computed by `getEmailOrigin` in `server/auth.ts`: it always prefers `APP_URL`, and in production it throws rather than falling back to `req.get("host")` so a forged Host header cannot poison verify or reset links. CSRF is enforced by `server/csrf.ts` using a double-submit cookie: a non-HttpOnly `csrf_token` cookie (SameSite=Lax, Secure in prod, 7d) is issued on every request, and any state-changing `/api/*` request must echo it in an `x-csrf-token` header (compared via `crypto.timingSafeEqual`). Exemptions: GET/HEAD/OPTIONS, the path prefixes `/api/telegram-webhook/`, `/api/widget/`, `/api/agent/`, `/api/public/`, and the exact paths `/api/billing/webhook`, `/api/auth/login`, `/api/auth/register`, `/api/auth/forgot-password`, `/api/auth/reset-password`, `/api/admin/login`. The frontend `apiRequest` helper in `client/src/lib/queryClient.ts` reads the cookie and injects the header on every non-safe method. The API access logger in `server/index.ts` redacts response-body fields whose key matches the explicit denylist (email, customerId, walletAddress, txHash, sessionId, refreshToken, accessToken, bankrApiKey, apiKey, privateKey, passphrase, csrfToken, tokenHash, passwordHash, etc.) or the regex `/(key|secret|token|password|passphrase)/i`; long values are masked to first2+***+last2 and short values to `[redacted]`, while `botToken` keeps its existing `slice(0,6)+***` shape.
**Telegram Bot Engine**: Modular, multi-instance architecture supporting isolated configurations for each bot, primarily via webhooks. Includes scam detection, AI response, conversation history, and real-time AI learning.
**AI Integration**: Leverages GPT-5.2 for scam detection and content moderation, and GPT-5-mini for conversational responses, all via Replit AI Integrations.
**Conversation Memory**: An in-memory ring buffer stores recent messages for AI context.
**Real-time Learning**: AI extracts and stores facts from messages into a bot's knowledge base.
**Multi-Bot Design**: All bot-specific data is scoped by `botConfigId`.
**Scam Detection**: Employs homoglyph normalization (Cyrillic/Greek lookalikes plus digit-for-letter swaps like 5→s, 0→o, 1→l, 3→e, 4→a, $→s — recovers "P0RN"/"LE5BIAN"/etc.), regex patterns, name impersonation detection, and GPT-5.2 as an AI fallback. Inline-keyboard button labels and URLs are extracted via `extractInlineButtonText` and concatenated into the scan payload by `buildScanText` so button-only forwarded ads (porn-channel grids, fake-giveaway drainer landing pages) are not skipped just because `msg.text` is empty. A structural rule `isButtonGridForwardSpam` (forwarded + ≥3 inline buttons + ≥2 external links) catches the same shape regardless of language. The `nsfwSpam` pattern catches porn-category keywords, "watch archive / hot girls / leaked" CTAs, and hard-no categories. Features report-based learning, configurable auto-ban, and per-bot scam sensitivity settings.
**Group Context**: Bots fetch and cache group descriptions and pinned messages for AI system prompts.
**Website Auto-scrape**: Bots can automatically scrape a configured `websiteUrl` for content.
**Master Agent (Agent-to-Agent API)**: An autonomous agent layer exposing TeliGent's scam detection and threat intelligence as public API services. Includes Locus payment integration, Self Protocol for proof-of-human identity, OpenServ marketplace integration, and ERC-8004 agent identity standard.
**Bankr Crypto Intelligence**: Optional per-bot feature integrating the Bankr REST API for real-time crypto data, enabling `/price` commands and enriching AI responses with market data.
**Passive CEO Rewards Loop**: Configurable per-bot system for reputation, leaderboards, proactive engagement, ERC-20 token rewards, and referral tracking.
**Proactive Community Feedback Loop**: Optional feature extending the proactive prompt engine to gather structured feedback, categorized and summarized by AI, presented in a dashboard.
**ERC-8004 Bot Registration on Celo**: Bots can register on the ERC-8004 Agent Identity Registry on Celo, creating an on-chain identity with bot stats.
**Helixa Onchain Identity (Base)**: Full read + write integration with the Helixa registry on Base (canonical ERC-8004 contract `0x8004A169FB4a3325136EB29fA0ceB6D2e539a432`). The read client `server/agent/helixa.ts` wraps the public `https://api.helixa.xyz/api/v2` endpoints (`/stats`, `/agent/:id`, `/agent/:id/cred`, `/name/:name`, `/search`) with a 5s timeout, single retry on 5xx only, Zod validation, structured `[helixa]` logs, and a 10-minute cache for network stats. The mint stack adds three modules: `server/agent/helixa-siwa.ts` (signs the "Sign-In With Agent: api.helixa.xyz wants you to sign in with your wallet {address} at {timestamp}" message with a viem account derived from `HELIXA_BASE_WALLET_PRIVATE_KEY`, caches the `Authorization: Bearer {address}:{timestamp}:{signature}` header for 50 minutes), `server/agent/helixa-x402.ts` (parses the HTTP 402 payment instruction, sends USDC.transfer on Base with the platform wallet, waits for receipt), and `server/agent/helixa-mint.ts` (transactional mint orchestrator with `BEGIN`/`SELECT FOR UPDATE`/`COMMIT`, idempotent re-mint guard, force-clear path, and fire-and-forget side effects: `linkTeliTokenForAgent` posts `/agent/:id/link-token` with `0x2822656E2Eec1c608a223752B4e0A651b50c4bA3` ($TELI) and stamps `helixa_link_token_at`; `verifyXOnHelixa`/`verifyGithubOnHelixa` are wired but only fire when an owner handle is present). Six additive `bot_configs` columns (`helixa_minted_at`, `helixa_tx_hash`, `helixa_base_token_id`, `helixa_link_token_at`, `helixa_x_verified_at`, `helixa_github_verified_at`) added via `ensureHelixaColumns` in `server/migrations.ts` (alongside the prior `helixa_agent_id`, `helixa_cred_score`, `helixa_cred_tier`, `helixa_profile_url`, `helixa_synced_at`). Routes: `GET /api/helixa/network-stats` (public, agent rate-limited), `GET /api/bots/:botId/helixa/status` (owner-gated; returns mint state, cred score with a 5-minute live-refresh gate, link-token timestamp, X/GitHub verification timestamps, BaseScan tx URL, and platform-wallet readiness — `walletConfigured` + `walletStatus: unconfigured | low | healthy | depleted` + `walletUsdc`), `POST /api/bots/:botId/helixa/register` (auth + `requireVerifiedEmail` + `requirePermission("allowErc8004")` + `apiRateLimit` + `requireBotOwnership`; idempotent — returns the existing record when `helixa_agent_id` is already set; returns 503 when the mint wallet env is missing or USDC < 1; payload derives `name = slug(botName)-teli-{botId}` plus `framework: "custom"`, `soulbound: true`, structured personality + narrative from the bot config), `POST /api/admin/bots/:botId/helixa/agent-id` (admin setter to attach or clear an agent ID; only stamps `helixa_synced_at` on a successful live fetch), and `POST /api/admin/bots/:botId/helixa/clear` (admin force-remint that wipes all `helixa_*` columns). A background sync `runHelixaSync` runs every `HELIXA_SYNC_INTERVAL_HOURS` (default 6h) and refreshes cred score + tier for all linked bots, emitting `[helixa.sync] refreshed=X skipped=Y failed=Z`. At boot, `server/index.ts` logs the platform wallet address, USDC, and ETH (`[helixa.wallet] ok address=… usdc=… eth=… status=…`); warns at <5 USDC, refuses to begin a mint at <1 USDC. Settings page now surfaces an active "Mint on Helixa (Base)" card: a wallet-status badge (`Ready` / `Low` / `Depleted` / `Not configured`), a single mint button gated on Pro plan + healthy wallet, and post-mint shows agent ID, base token ID, BaseScan tx link, profile link to `helixa.xyz/agent/:id`, plus `$TELI linked` / `X verified` / `GitHub verified` badges. Master Agent page still surfaces a "Helixa Network (Base)" panel showing total agents, mint price, and supported frameworks.
**Plans & Billing**: Three SaaS tiers (Free, Pro, Business) with features and quotas defined in `server/limits.ts`. Supports Stripe for card payments and crypto payments on Base (USDC + $TELI) via on-chain transfer monitoring. $TELI token offers perks like discounts and rewards multipliers. Paywall enforcement is managed by `server/billing/gates.ts`. Crypto checkout uses a live $TELI/USD price oracle (`server/billing/teli-price.ts`) — DexScreener pair price is the primary source, Bankr API is the fallback, results are cached for 5 minutes, and admins can set a manual override via `platform_settings.usd_per_teli` (cleared via the admin "Use live" button). The billing UI shows a live quote with rate source/timestamp before the user generates a payment intent. Each pending intent has a manual tx-hash claim path (`POST /api/billing/crypto/intent/:id/claim`) that performs strict validation (token + receive-address + EXACT atomic-unit amount + post-intent timestamp) and is protected against tx-hash replay across intents by a partial unique index `idx_plan_payment_intents_matched_tx_unique` on `plan_payment_intents.tx_hash WHERE status='matched'`. The poller (`pollCryptoIntents`) uses retry-with-jittered-backoff, doubles the block lookback on retry, and emits a per-cycle structured log line. After successful payment, a persistent banner on the billing page surfaces the activation until dismissed (tracked in localStorage by `planPeriodEnd`), and `/api/me/limits` is auto-invalidated every 10s while a pending intent exists.
**Production Configuration**: Includes robust session secret validation, centralized resource limits (`server/limits.ts`), daily AI call budget enforcement via `ai_usage_daily` table, and widget origin allowlisting.
**Public Activity Feed**: Bots can opt in via `bot_configs.shareAnonymizedEvents` (off by default). When opted in, the public `GET /api/public/recent-events` endpoint streams the last 24h of category-only events (scam_removed, ai_answer, reward, new_member) with telegram handles redacted to a salted `@x***NN` form and bot identity hidden behind "a community". Output is capped at 12 events and cached in-memory for 30s. The landing page hero card includes a `live-feed` scenario that polls this endpoint and falls back to a scripted scenario when the feed is empty.
